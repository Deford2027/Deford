# OpenRouter — подбор кандидатов и справка

Единый API к моделям разных вендоров: **445 текстовых моделей** плюс около 140,
которых в API нет вовсе.

## Твоя роль: дать кандидатов, а не выбрать за владельца

Порядок в работе владельца такой: он получает **список моделей под задачу** →
сам их прогоняет на своём материале → **сам принимает решение**, зная цену и
увидев качество.

Значит от тебя нужны **факты и кандидаты**, а не вердикт:

- цена, скорость, контекст, потолок вывода, что модель умеет — это факты каталога;
- **качество ты не знаешь и не измерял.** «Лучше», «мощнее», «качественнее» без
  замера — выдумка, которая потом ломает работу;
- дорогая ≠ подходящая. Не сортировать кандидатов по цене как по качеству;
- если владелец спросил «что взять» — дать 2–4 кандидата с фактами и разницей
  между ними, и сказать прямо: сравнивать надо прогоном.

Выдумывать оценки нельзя даже правдоподобные: владелец на них построит выбор,
а проверить их будет нечем.

**Каталог живёт своей жизнью.** Модели выходят каждую неделю, цены и скидки
меняются. Перед ответом свериться запросом, а не цитировать по памяти.

Полный разбор возможностей по задачам — `references/возможности.md`.


поставить новую дату.

## Порядок работы

1. **Понять тип задачи** — текст, звук, картинка, поиск по смыслу.
2. **Свериться с каталогом**: `GET /api/v1/models` для текстовых, веб-каталог для
   остальных. Не по памяти.
3. **Отобрать 2–4 кандидата** и назвать разницу между ними фактами: цена,
   скорость, контекст, потолок вывода, что умеет.
4. **Посчитать цену** на реальном объёме задачи — это арифметика, а не мнение.
5. **Сказать прямо, что качество не измерено** и сравнивать надо прогоном.
6. **Сказать, если задача решается дешевле в другом месте** — честнее, чем
   продать OpenRouter любой ценой.

## Как считать цену

| Где | Что означает число | Формула |
|---|---|---|
| API `pricing.prompt` | цена за **ОДИН токен** | `токены × цена` |
| Таблицы и веб-каталог | цена за **МИЛЛИОН** | `токены × цена / 1e6` |

Обе верны для своего представления. Проверка на глаз: обычный запрос — центы.

**Поиск и картинки тарифицируются отдельно** и в `usage` не видны: `pricing.web_search`
за поисковый запрос, `image_output` за картинку. Замерено: у поисковой модели оценка
по одним токенам занижала счёт **в 5 раз**.

**Фактическая цена** — `GET /api/v1/generation?id=…` → `total_cost`. Баланс для
сверки одного запроса не годится: он обновляется с задержкой.

## Потолок вывода — проверять до запуска

У моделей разный физический максимум ответа: у поисковых Perplexity — **8 000**
токенов, у Gemini 65 536, у Grok 450 000. Смотреть `top_provider.max_completion_tokens`.

Просить больше потолка бессмысленно: провайдер режет, возвращает `length`, а попытка
**оплачена**. Так три бесполезных повтора однажды сожгли 0.34. USD

## Экономия

| Приём | Выигрыш |
|---|---|
| Суффикс `:batch` | **вдвое дешевле**, но без гарантии времени |
| Суффикс `:free` | бесплатно; есть у десятков моделей |
| Скидки | видны только в веб-каталоге как «50% off», в API их нет |
| Кэш ввода | у части моделей `input_cache_read` дешевле обычного ввода |
| `openrouter/auto` | платформа сама выберет модель под запрос |

## Ловушки

**`transforms: []` в каждом запросе** — иначе OpenRouter **молча режет длинный вход**,
и модель честно отвечает на обрубок.

**Строки `(batch)` в веб-каталоге стоят рядом с обычными** и стоят иначе. Однажды
так была взята цена batch-версии вместо живой.

**Флагман нельзя искать сортировкой по цене** — наверх лезут старые дорогие модели.
Фильтровать по вендору, сортировать по `created`.

**Провайдер может подменить модель.** Сверять `model` в ответе с запрошенной.

## Запрещено / разрешено

| ❌ Запрещено | ✅ Разрешено |
|---|---|
| Называть модели и цены по памяти | Свериться с каталогом перед ответом |
| Запустить платную генерацию молча | Назвать цену и дождаться согласия |
| Считать цену без надбавок за поиск и картинки | Учитывать всё, что вне токенов |
| Просить больше потолка модели | Проверить `max_completion_tokens` |
| Выдавать оценку за факт | Сверить через `/generation?id=` |
| Тащить сюда медиа-задачи | Отправить в «segmind», там их больше |
| Оценивать качество, которого не мерил | Давать факты и предлагать прогон |
| Сортировать кандидатов по цене как по качеству | Показывать разброс и разницу |
| Решать за владельца, что «лучше» | Дать кандидатов — решает он после теста |

**Главное:** давать кандидатов с фактами, а решение оставлять владельцу — он
тестирует сам. Качество не выдумывать: не мерил — так и сказать. Сверяться с
каталогом, а не с памятью. Цену считать на реальном объёме, с надбавками за поиск
и картинки. Потолок вывода проверять до запуска.
