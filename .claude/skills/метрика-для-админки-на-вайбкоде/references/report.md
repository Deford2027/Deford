Читать на шаге 4 (модуль данных) и шаге 5 (экран). Эталон – EV SIBIR,
`~/Documents/ev-sibir/server/`: `metrika.py` (доступ к API), `metrika_report.py`
(отчёт), `gsc.py` (Search Console), `metrika_view.py` (экран). Коммиты
b1acda7, c12defa, 9f035bb, 148ac27, 69b7dfb, f7eb1eb (14.10.2026), репозиторий
tema-mail/ev-sibir. Макет: https://claude.ai/artifact/QDB3snUcEiiZcUcTG8QWd1

Код эталона – Python stdlib, без зависимостей. В другой админке (Node, Django,
FastAPI) переносить логику и формулы, а не файлы целиком.

## Архитектура

- Страница админки читает только кэш (JSON-файл) и открывается сразу.
- Кнопка «Обновить» (POST за авторизацией) опрашивает API и перезаписывает кэш.
- Запись кэша – во временный файл и `replace`, под блокировкой: два нажатия подряд не
  запускают два опроса.
- Каждый блок – в своём `try`: ошибка блока даёт `None` и строку в `errors`, остальное
  работает. Если не пришло ничего – старый кэш не затирать, писать `last_error`.
- Search Console – отдельным `try … except Exception` **на каждую вкладку**: битый ключ
  не должен ронять цифры Метрики, а сбой «Показателей» – блок Google в «Сравнении» (оба
  случая ловил ревизор 14.10.2026).

## Периоды (все даты – в часовом поясе счётчика, `time_zone_name`)

`end` – последний полный день (обычно вчера; сегодня не берём – Метрика досчитывает).

| Режим | Сейчас | Сравнение |
|---|---|---|
| Год к году | `end−27 … end` (28 дней) | минус **364** дня – те же дни недели |
| Месяц к месяцу | последний **полный** месяц | месяц перед ним |
| Квартал к кварталу | последний полный квартал | квартал перед ним |
| Неделя к неделе | `end−6 … end` | `end−13 … end−7` |

Отставание Метрики: по дням за 21 день; день, где визитов меньше трети медианы
прошлых 7 дней, – недосчитан, `end` уходит назад. Проверку не включать, если медиана
меньше 20 визитов в день (маленький сайт – провал в один день норма). Год к году и
неделю сдвигать, месяц и квартал – только плашка.

## Две вкладки (владелец, 14.10.2026)

«Сначала сравнение – непонятно. Мне нужны показатели за неделю, месяц, квартал, год, а
сравнение отдельно». Поэтому вверху переключатель **«Показатели | Сравнение»**, по
умолчанию – «Показатели»:

- **Показатели** – периоды в порядке владельца: неделя (7 дн.), месяц (30), квартал (91),
  год (365), все по последний полный день, без «против» и без стрелок изменений. Блоки:
  8 плиток → каналы → визиты из поиска **двумя линиями Яндекс и Google** (по дням до 31 дня,
  дальше по неделям от конца) → страницы входа из поиска **колонками Яндекс / Google /
  Всего / Заявки** → цели × источники → «Поиск в Яндексе» и «Поиск в Google» рядом.
- **Сравнение** – год к году, месяц к месяцу, квартал к кварталу, неделя к неделе (таблица
  периодов выше). Блок разницы по страницам называть понятно: «Где переходов из поиска
  стало меньше или больше» с объяснением, что минус – страницу стали реже находить.
- Параметры страницы `v` (вкладка), `p` (период), `c` (режим) – только по белым спискам;
  старая ссылка с одним `c` открывает «Сравнение».

## Поиск в Яндексе без Вебмастера

Метрика отдаёт фразы Яндекса: группировка `ym:s:lastsignSearchPhrase` с фильтром
`ym:s:lastsignSearchEngineRoot=='yandex'`. Google фразы скрывает – их только из Search
Console. Итог запроса с группировкой фраз **не включает** визиты со скрытой фразой:
все визиты из Яндекса брать отдельным запросом без группировки, «фраза скрыта» = все −
сумма строк (на EV 14.10: год – 34 визита, у 13 фраза скрыта). Показы и позиции Яндекса –
только Вебмастер. Блок «Поиск в Яндексе» – **тот же вид, что «Поиск в Google»** (владелец
14.10.2026): карточка с шапкой, период, 4 цифры, таблица запросов. С Вебмастером – клики, показы,
CTR, позиция + колонка «Отказы» из Метрики по совпадению фразы; без него – визиты, отказы,
заявки, «фраза скрыта» из Метрики и пояснение с причиной из последнего обновления.
Вебмастер (эталон `server/ywm.py`): GET /v4/user → user_id; /v4/user/{uid}/hosts → ровно наш
host_id (`https:домен:443`, не www); search-queries/all/history (TOTAL_SHOWS, TOTAL_CLICKS,
device_type_indicator=ALL) и search-queries/popular (order_by=TOTAL_SHOWS, + AVG_SHOW_POSITION,
limit=500), даты `YYYY-MM-DDT00:00:00%2B07:00`. Сначала проверка /v4/user с таймаутом 10 с: не
ответил – одна ошибка `ywm_error` рядом с блоком, не в общем списке. С 11.10.2026 API не
отвечал по сети – разбор ответа сверить на живом ответе при первой возможности.

## Блоки и запросы (stat/v1/data, accuracy=full, lang=ru)

Во все запросы – фильтр `ym:s:isRobot=='No'` («только люди»); если есть свой фильтр –
`(свой) AND ym:s:isRobot=='No'`.

| Блок | Группировки | Метрики | Заметки |
|---|---|---|---|
| Плитки | – | visits, users, percentNewVisitors, bounceRate, pageDepth, avgVisitDurationSeconds, goal{id}reaches | сейчас и сравнение; доли – изменение в п.п. |
| Каналы | lastsignTrafficSource, lastsignSearchEngineRoot | visits, goal{lead}reaches | organic делить на Яндекс/Google; нейросети – по домену lastsignReferalSource |
| Поиск по неделям | ym:s:date + фильтр `lastsignTrafficSource=='organic'` | visits, goal{lead} | недели по 7 дней **от конца** периода, иначе теряются свежие дни |
| Страницы входа из поиска | startURLPath + organic | visits, goal{lead} | сумма строк < итога – добавить строку «адрес скрыт Метрикой» |
| Потеряли / набрали | то же за оба периода | visits | разница по адресу, без строки «адрес скрыт» |
| Цели × источники | как каналы | visits + reaches каждой цели | источники от N визитов; конверсия = reaches / visits |

Заявки «все» – из своей базы заявок, а не из Метрики (Метрика видит только согласных на
cookie). Конверсию и заявки по каналам – целью Метрики: визиты и заявки по одним людям.
Сравнение заявок из базы – только если база существовала в начале периода сравнения.

Нейросети: chatgpt.com, openai.com, perplexity.ai, gemini.google.com,
copilot.microsoft.com, claude.ai, deepseek.com, alice.yandex.ru, giga.chat, grok.com,
poe.com, you.com, chat.mistral.ai – совпадение домена или поддомена.

## Search Console (searchAnalytics/query)

- Доступ сервисного аккаунта: JWT RS256, scope `webmasters.readonly`, подпись openssl
  (без сторонних библиотек), временный файл ключа – внутри `try`, удалить в `finally`.
- Последние 2–3 дня у Google недосчитаны: если период заходит на них, сдвинуть **оба**
  периода назад на одно и то же число дней и показать реальные даты.
- По режиму: итоги без группировок (clicks, impressions, ctr, position) сейчас и в
  сравнении; топ-20 запросов (`dimensions: ["query"]`) и позиции тех же запросов в
  сравнении; рост позиции = старая − новая > 0.
- Новый ресурс отдаёт нули за прошлое – показывать «не с чем сравнить», не «−100%».

## Экран

- Сервер рендерит HTML: полосы – `width: N%`, недельный график – SVG из чисел.
- Всё из API (адреса, запросы, названия, тексты ошибок) – через escape. Режим из
  параметра – только по белому списку.
- Порядок по макету: шапка (режимы, даты «Период … против …», «только люди») → плашка
  отставания → 8 плиток (4×2, на телефоне 2×4) → пояснение «почему заявок в базе больше» →
  каналы → поиск по неделям → страницы входа | потеряли/набрали → цели × источники →
  Google → список ошибок.
- Проверить 4 режима, пустой кэш, блоки `None`, ширины 375 и 1280 без горизонтальной
  прокрутки.
