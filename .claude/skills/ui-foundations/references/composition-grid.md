# Composition and grids

## Begin with hierarchy

Write a priority order for the screen before placing elements. Make that order
visible through several coordinated variables:

- position and reading order;
- scale and weight;
- contrast and color;
- whitespace and grouping;
- repetition and alignment;
- depth or motion only when they encode meaning.

A single oversized heading does not repair a flat composition. Conversely, if
everything is emphasized, nothing is emphasized.

## Gestalt relationships

- **Proximity:** related controls and information sit closer together than
  separate groups.
- **Similarity:** repeated appearance implies repeated behavior or category.
- **Common region:** cards, rules, or background fields should express a real
  grouping, not decorate every fragment.
- **Continuity and alignment:** persistent edges help the eye scan and compare.
- **Figure and ground:** foreground actions must remain distinct from surfaces
  and decoration.

Do not violate these cues accidentally. A visually identical control should not
perform a different kind of action.

## Choose a grid for the content

- Use a 4-column structure as a common mobile starting point, 8 for many tablet
  arrangements, and 12 for flexible desktop compositions. These are options,
  not mandatory device rules.
- Define container width, outer margins, gutters, column behavior, and nested
  component grids together.
- Align important boundaries and baselines. A grid is a system of relationships,
  not a visible checkerboard.
- Use a baseline rhythm for repeated text-heavy rows, tables, and editorial
  surfaces when it improves scanning.
- Let regions span different column counts according to importance and content.
  Break the grid deliberately for emphasis, never because the system was not
  defined.

## Balance, rhythm, and whitespace

- Balance visual mass, not only geometric dimensions. Dark, saturated, detailed,
  or animated elements carry more weight.
- Repeat intervals to establish rhythm, then vary them at meaningful boundaries.
- Treat whitespace as an active separator and pacing device.
- Avoid “card soup”: use cards only when content needs an independent boundary,
  action context, selection state, or portability. Prefer headings, spacing,
  rules, and alignment for ordinary grouping.
- Dense operational dashboards can be compact, but compactness must not erase
  hierarchy, targeting, or scan paths.
